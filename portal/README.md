# SkillPortal setup (XAMPP)

## Requirements

- XAMPP with Apache, MySQL, PHP 8.0 or newer, and the `pdo_mysql` and `fileinfo` PHP extensions enabled.
- PHP upload limits of at least 5 MB (`upload_max_filesize = 6M` and `post_max_size = 7M`). Restart Apache after changing `php.ini`.

## Install

1. Copy the `portal` folder into XAMPP's `htdocs` directory, for example `C:\xampp\htdocs\skillportal`.
2. Start **Apache** and **MySQL** from the XAMPP control panel.
3. Open `http://localhost/phpmyadmin/`, select **Import**, choose `database/schema.sql`, and run the import. The SQL creates the `skillportal` database and demo records; it uses `IF NOT EXISTS` and `INSERT IGNORE`, so it does not drop existing tables or overwrite existing demo users.
3. Open `http://localhost/phpmyadmin/`, select **Import**, choose `database/schema.sql`, and run the import. This is the single canonical schema and creates the `skillportal` database and demo records. It uses `IF NOT EXISTS` and `INSERT IGNORE`; it will not drop existing tables or overwrite existing demo users, but it also will not upgrade the structure of tables that already exist. Back up existing data before replacing an older database.
4. Check `api/config/db.php` if your MySQL host, database name, user, or password differs from the XAMPP defaults. The default is `127.0.0.1`, database `skillportal`, user `root`, and an empty password. Environment variables `SKILLPORTAL_DB_HOST`, `SKILLPORTAL_DB_NAME`, `SKILLPORTAL_DB_USER`, and `SKILLPORTAL_DB_PASSWORD` can override these defaults.
5. Ensure Apache can write to `api/storage/uploads/` and `storage/`. The upload folder denies direct web access with its `.htaccess` file; `storage/superadmin.json` contains non-secret system configuration.
6. Open `http://localhost/skillportal/`. Do not launch the HTML files with `file://`; the pages need the PHP API and its session cookie.

The database stores a bcrypt hash generated by PHP `password_hash()`. Change all demo passwords before using the portal beyond local testing.

## API notes

The frontend uses `assets/js/api.js` for same-origin JSON requests. API errors are returned as JSON. Uploaded proof and transfer files accept PDF, JPEG, or PNG up to 5 MB and are assigned random filenames. Attendance coordinates are checked by the server against the active session time window and campus geofence; browser-provided coordinates can still be spoofed, so production attendance should use additional device or identity controls.
